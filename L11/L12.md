# Ejercicio 3 — Sistema de Gestión de Personal

**Categoría:** Organizing Data + Generalización
**Técnicas a aplicar:** Replace Data Value with Object, Pull Up Method, Push Down Method, Extract Subclass

## Contexto

La empresa **NovaTech** administra empleados con una jerarquía `Empleado` → `EmpleadoTiempoCompleto`, `EmpleadoTiempoParcial`, `EmpleadoVentas`. El código tiene datos primitivos que deberían ser objetos, métodos duplicados en subclases y un método que solo tiene sentido para un tipo de empleado.

## Código original

```java
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;

public abstract class Empleado {
    protected String nombre;
    protected String codigoPostal; // dato primitivo sin validación centralizada
    protected LocalDate fechaIngreso;

    // Solo tiene sentido para empleados de ventas, pero vive en la superclase
    protected double totalVentasMes;

    public Empleado(String nombre, String codigoPostal, LocalDate fechaIngreso) {
        this.nombre = nombre;
        this.codigoPostal = codigoPostal;
        this.fechaIngreso = fechaIngreso;
    }

    public String getCodigoPostal() { return codigoPostal; }

    public double calcularBonoVentas() {
        return totalVentasMes * 0.05;
    }

    public abstract double calcularSalario();
}

class EmpleadoTiempoCompleto extends Empleado {
    private double salarioBase;

    public EmpleadoTiempoCompleto(String nombre, String codigoPostal, LocalDate fechaIngreso, double salarioBase) {
        super(nombre, codigoPostal, fechaIngreso);
        this.salarioBase = salarioBase;
    }

    @Override
    public double calcularSalario() {
        return salarioBase;
    }

    // Duplicado en EmpleadoTiempoParcial
    public long calcularAntiguedadEnAnios() {
        return ChronoUnit.YEARS.between(fechaIngreso, LocalDate.now());
    }
}

class EmpleadoTiempoParcial extends Empleado {
    private double tarifaPorHora;
    private int horasTrabajadas;

    public EmpleadoTiempoParcial(String nombre, String codigoPostal, LocalDate fechaIngreso,
                                  double tarifaPorHora, int horasTrabajadas) {
        super(nombre, codigoPostal, fechaIngreso);
        this.tarifaPorHora = tarifaPorHora;
        this.horasTrabajadas = horasTrabajadas;
    }

    @Override
    public double calcularSalario() {
        return tarifaPorHora * horasTrabajadas;
    }

    // Idéntico al de EmpleadoTiempoCompleto: candidato a Pull Up Method
    public long calcularAntiguedadEnAnios() {
        return ChronoUnit.YEARS.between(fechaIngreso, LocalDate.now());
    }
}

class EmpleadoVentas extends Empleado {
    private double salarioBase;

    public EmpleadoVentas(String nombre, String codigoPostal, LocalDate fechaIngreso, double salarioBase) {
        super(nombre, codigoPostal, fechaIngreso);
        this.salarioBase = salarioBase;
    }

    @Override
    public double calcularSalario() {
        return salarioBase + calcularBonoVentas();
    }

    public void registrarVenta(double monto) {
        this.totalVentasMes += monto;
    }
}
```

Además, RRHH pidió que los **gerentes** (un subconjunto de `EmpleadoTiempoCompleto`) tengan un campo `presupuestoAsignado` y un método `aprobarGasto(double monto)`. Actualmente esto se maneja así, con un flag booleano y condicionales dispersos:

```java
class EmpleadoTiempoCompletoConFlag extends Empleado {
    private double salarioBase;
    private boolean esGerente;       // flag que debería ser una subclase
    private double presupuestoAsignado;

    public EmpleadoTiempoCompletoConFlag(String nombre, String codigoPostal, LocalDate fechaIngreso,
                                          double salarioBase, boolean esGerente, double presupuestoAsignado) {
        super(nombre, codigoPostal, fechaIngreso);
        this.salarioBase = salarioBase;
        this.esGerente = esGerente;
        this.presupuestoAsignado = presupuestoAsignado;
    }

    @Override
    public double calcularSalario() {
        return esGerente ? salarioBase * 1.2 : salarioBase;
    }

    public boolean aprobarGasto(double monto) {
        if (!esGerente) {
            throw new UnsupportedOperationException("Solo un gerente puede aprobar gastos");
        }
        return monto <= presupuestoAsignado;
    }
}
```

## Tareas

1. **Replace Data Value with Object:** `codigoPostal` es un `String` suelto que en el sistema real necesita validación de formato. Crea una clase `CodigoPostal` que lo encapsule y reemplázalo en `Empleado`.
2. **Pull Up Method:** `calcularAntiguedadEnAnios()` está duplicado idéntico en `EmpleadoTiempoCompleto` y `EmpleadoTiempoParcial`. Súbelo a `Empleado`.
3. **Push Down Method:** `calcularBonoVentas()` vive en `Empleado` pero solo lo usa `EmpleadoVentas`. Bájalo a esa subclase.
4. **Extract Subclass:** el flag `esGerente` en `EmpleadoTiempoCompletoConFlag` controla comportamiento condicional. Extrae una subclase `Gerente extends EmpleadoTiempoCompleto` que contenga `presupuestoAsignado` y `aprobarGasto()`, eliminando el flag.

## Restricciones

- `calcularSalario()` debe seguir devolviendo el mismo valor para cada tipo de empleado existente.
- `aprobarGasto()` solo debe existir en `Gerente`, no en `Empleado` ni en `EmpleadoTiempoCompleto`.
